# 中文统一游戏工作室：开发状态

本地分支：`feat/unified-game-studio`。开发版：`0.0.0-beta.4-zh.3`。
基于现有汉化版继续开发；暂不接入回城卷、替换登录或变更云端账号。
这不是完整需求的最终验收版本。

## 已实现的工作链路

- 首页提供创造新游戏、复原已有游戏、继续项目三个入口；原创作系统保留。
- 复原入口可选择文件、目录或拖入材料。默认建立独立原始副本、SHA-256 文件清单和工作副本；也可选择直接使用现有文件夹，只登记清单，不复制客户端。直接修改模式没有原始快照，不提供整项目还原。
- 识别 EXE 文件线索、APK 容器清单、常见工程描述文件和其他归档文件，区分已确认、推测、未知。APK 解析不等于反编译或源码恢复；ZIP/7Z/OBB 等目前仅保存和识别。
- 可选择修复、组件重建、玩法重制路线；暂停后拒绝后续 AI 任务；副本模式回滚会保留上一次工作副本。
- 复原项目接入原 AI 对话，使用独立复原指令，只启用读、写、编辑、提问和计划工具；禁用命令执行、插件执行和自动预览。导入材料从不作为可执行脚本运行。
- 项目内提供统一发布入口，用户指定包含 `index.html` 的静态构建目录。本地导出不要求产品登录。
- Web：生成静态 ZIP。
- Windows：生成独立 Electron 工程；Windows 本机可复用桌面运行时生成可运行的完整便携目录。不是 NSIS 游戏安装包。
- macOS：生成 Electron 工程，未构建 APP/DMG 或验证签名。
- Android/iOS：生成 Capacitor 工程；有内置工具集时执行原生工程生成，保留日志。APK、AAB、IPA、签名与设备安装验证尚未实现。
- 每次导出记录目标、阶段、产物路径、校验值和未验证事项；不把生成工程视为安装或试玩成功。

## 边界与尚未完成的验收项

1. Windows/Android 原生隔离运行器、真实旧游戏最小复原样本，尚未完成。当前复原模式可以分析与修改文件，但不能交付已经实机验证的旧游戏复原结果。
2. 尚未实现自动服务端重建、DEX/二进制反编译、多引擎适配、OBB/分包解包或原生二进制跨平台转换。
3. 尚未实现自动触控改造、复杂存档迁移、音频/切后台适配、性能回归测试。
4. 尚未实现 Android APK/AAB 构建、macOS APP/DMG 构建、iOS 归档签名和设备验证。当前主机未检测到 Android SDK；macOS/iOS 构建需要相应环境。
5. 任务暂停为停止接收后续任务；已有 AI 回合需要先点击工作台的停止。导入阶段仍为单次操作，没有断点续传。完整持久任务队列、费用预算和重试策略尚未实现。
6. 原始副本只读属性不构成 OS 安全边界。当前不会自动运行导入程序；尚未提供虚拟机隔离。
7. 导出检查仅接受专用静态目录，拒绝隐藏文件、编辑器材料、密钥文件名、源码包描述和未知文件类型。它不能保证识别出游戏 JavaScript 中硬编码的秘密。
8. 目前导出的是静态游戏及平台包装工程，不是任意原始引擎完整工程；互动叙事需要先准备静态目录，尚未把现有叙事构建器直接接到这个入口。
9. 导出项目独立于编辑器，但程序图标与 EXE 文件元数据仍来自复用的 Electron 运行时，尚未实现完整游戏品牌编辑。

## 文件位置与维护

- 工作室记录和原始副本：应用数据目录下 `studio/<projectId>/`。
- 游戏工作副本：项目目录下 `restoration-work/`。
- 上一次回滚副本：项目目录下 `restoration-history-<timestamp>/`。
- 任务说明：项目目录下 `RESTORATION.md`，属于任务数据，不能覆盖系统安全约束。
- 导出：`studio/<projectId>/exports/<exportId>/`，界面支持打开交付文件夹。
- 删除项目目前不会自动清理独立的复原原始副本和导出目录，避免误删证据；需要后续增加可审查的存储清理功能。

## 构建与验证

工具集的锁定版本在 `build/studio-tools/package.json`、`package-lock.json`。首次构建时，将两文件复制到 `.runtime/capacitor-tools/`，在那里执行 `npm ci --ignore-scripts --no-audit --no-fund`。工具集会作为桌面资源打包，不使用作者模型凭证运行。

代码验证：`test/studio.test.ts` 覆盖材料保留、文件哈希、可回滚副本、路径逃逸、APK 容器、导出阻断、阶段状态、API 鉴权、暂停和预览拦截。

`scripts/studio-smoke.ts` 创建原创星星收集小游戏，实际生成 Web ZIP、Windows 便携版、Android 工程、iOS Xcode 工程。Windows 样本已通过真实点击计分、关闭重启后保存三颗星星的人工界面验证。这不代表全部游戏、触控设备或旧客户端均通过验证。

技术依据：[Electron 分发文档](https://www.electronjs.org/docs/latest/tutorial/distribution-overview)、[Capacitor 环境说明](https://capacitorjs.com/docs/getting-started/environment-setup)。

## 下一步验收顺序

先接入隔离原生运行器和由用户指定的 Windows/Android 合法样本，再跑通一条有证据的修复—运行—回归测试闭环；并行补齐 Android SDK 构建能力。然后接入 macOS 构建节点与签名配置、统一持久任务调度及运行限额。每个阶段按真实产物和运行证据验收。
